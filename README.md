# Tailoring workflow

## 1. Read the posting

Extract:

- Job title and company.
- Location and working arrangement.
- Contract type and salary, if stated.
- Main responsibilities and expected results.
- Must-have and preferred qualifications.
- Relevant terminology, tools, laws, frameworks, and document types.

Use the official employer posting when accessible. If a link cannot be opened, request the full text. Do not treat a search snippet as a complete posting.

## 2. Assess fit

Classify material requirements as:

- **Confirmed:** directly supported by evidence.
- **Partly confirmed / transferable:** supported by related experience; explain the connection.
- **Unconfirmed:** not established in the available materials.
- **Confirmed gap:** evidence establishes that I do not meet it.

Missing information is not proof of missing experience.

Do not require a perfect match. Support reasonable stretch applications while clearly identifying significant differences in core function or mandatory qualifications.

Present gaps as a concrete numbered list. Put clarification questions separately.

## 3. Select the strongest evidence

Identify my strongest confirmed reasons for being considered.

Select experience that demonstrates relevant responsibilities, results, scope, and transferable skills. Put the most relevant bullets first within each role.

Maintain a clear chronology. Do not copy the posting’s requirements into my resume as if they were completed work.

## 4. Rewrite

Adapt the headline, Summary, Core Skills, experience bullets, and relevant supporting sections.

Use the posting’s terminology when it truthfully describes my experience. Explain specialized abbreviations once where useful.

Write specific, natural bullets showing what I did, the context or scope, and the result when known.

**No mandatory XYZ formula applies.** Use the structure that best communicates each confirmed contribution.

Use numbers only when confirmed. Qualitative outcomes and concrete responsibilities are acceptable. Do not force a metric into every bullet.

Use present tense for ongoing responsibilities and past tense for completed achievements and previous roles.

Avoid generic self-praise and unsupported claims. Each bullet must add useful evidence.

## 5. Review relevance

Check that important, supported requirements are easy to find.

There is **no minimum keyword percentage**. Do not add unsupported keywords, stuff terms into the document, or delay completion because some requirements cannot truthfully be covered.

Prepare the strongest truthful version and explain the remaining gaps.

## 6. Obtain approval and deliver

Present the complete resume for my review. Keep review drafts outside the final company folder.

Apply my corrections and obtain my explicit approval of the resume content. Then export, verify, and save the final PDF in the agreed location.

If exporting requires any substantive content changes, obtain approval for those changes before saving the final version.

# ATS formatting: Greenhouse only

Use this official source for ATS parsing guidance:

https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse

Do not use Virginia Tech, Jobscan, or other third-party advice as the basis for ATS rules.

Based on the parsing problems described by Greenhouse:

- Use a single-column layout with clear sections and consistent formatting.
- Avoid tables, text boxes, photos, graphics, and WordArt.
- Keep my name and contact details in the document body, not headers or footers.
- Do not insert spaces between letters for decorative effects.
- Use full job titles rather than unclear abbreviations.
- Produce a text-based PDF, not a scan or image.
- Keep the file within Greenhouse’s 2.5 MB parsing limit.
- Use real employer names. Do not invent legal suffixes or other details to improve parsing.

Project formatting preferences:

- Arial or Calibri, 10.5–12 pt.
- Plain bullets and readable spacing.
- Consistent date format, such as `Oct 2023 – Present`.
- Plain-text skills rather than graphical ratings.
- English throughout; follow the posting’s spelling, using US spelling for US companies.

Correct parsing does not guarantee selection. Never claim that a file has been tested in Greenhouse unless that test actually occurred.

# Quality checks

Before presenting a resume for approval:

1. Trace every factual statement to a confirmed source.
2. Verify names, titles, dates, credentials, and language levels.
3. Check the three-sentence Summary and 5–7 bullets per position.
4. Check relevance, clarity, grammar, and consistency.
5. Remove placeholders, internal notes, and unsupported claims.

Before saving the approved PDF:

1. Verify the rendered resume is no longer than two pages and has readable formatting.
2. Check for clipping, awkward page breaks, blank pages, and missing text.
3. Confirm that text is selectable and can be extracted in the correct order.
4. Check that the exported content matches the approved version.
5. Verify the filename, company folder, and file size.
6. Apply equivalent factual, visual, and text-extraction checks to the cover letter.

Text extraction is a useful check, not proof of successful Greenhouse parsing.

If file creation or saving is unavailable, explain the limitation and provide the complete document text for review. Clearly state that PDF delivery, layout verification, or saving remains incomplete. Do not claim that a file was created or saved when it was not.
